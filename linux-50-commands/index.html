Before we start

Your lab & the rules

  • Practise on systems you own — a Kali VM plus one or two target VMs on a host-only network (e.g. 192.168.56.0/24).
  • Scanning or testing other people's systems without written permission is illegal in most countries. scanme.nmap.org is one host that explicitly allows light scanning.
  • Take snapshots before you experiment, so you can always roll back.
  • Output in these slides is example output from a lab: your numbers will differ.

pwd

Prints the full path of the directory you are currently in.

pwd [-P]

-Pshow the physical path (resolve symlinks)
-Lshow the logical path (default)
Security use

Always confirm where you are before running commands that change or delete files during an investigation.

kali@kali: ~
kali@kali:~$ pwd
/home/kali
kali@kali:~$ cd /var/log && pwd
/var/log
kali@kali:~$ cd /tmp/link-to-logs && pwd -P
/var/log
kali@kali:~$
▶ Practice Make a symlink to /etc in your home folder, cd into it, and compare pwd with pwd -P.

Lists directory contents, including hidden files and permissions.

ls [options] [path]

-llong format: permissions, owner, size, date
-ainclude hidden (dot) files
-hhuman-readable sizes

Hidden files and odd permissions are often the first clue when auditing a home folder or web root.

Changes the current working directory.

cd [directory]

cd -jump back to the previous directory
cd ..go up one level

Moving quickly between /var/log, /etc and /tmp is the backbone of every triage session.

/etc/ssh
kali@kali:~$ cd -
/home/kali
kali@kali:~$ cd ../..
kali@kali:~$ pwd
/
kali@kali:~$

08/50 Files & Navigation

find

Searches the filesystem by name, type, size, owner, time or permission.

find [path] [tests] [actions]

-namematch a filename pattern
-permmatch permissions (e.g. -4000 for SUID)
-mtimemodified N days ago
-userowned by a user
Security use

Auditors hunt for SUID binaries, world-writable files and recently changed files after an incident.

kali@kali: ~
kali@kali:~$ find / -perm -4000 -type f 2>/dev/null | head -4
/usr/bin/passwd
/usr/bin/sudo
/usr/bin/mount
/usr/bin/su
kali@kali:~$ find /etc -mtime -1 -type f 2>/dev/null
/etc/hosts
kali@kali:~$ find /tmp -perm -o+w -type f
/tmp/build.lock
kali@kali:~$
▶ Practice Find every file in /etc modified in the last 7 days, and every SUID file on your system.

09/50 Files & Navigation

file

Identifies a file's real type by its content, not its extension.

file [options] file...

-bbrief: omit the filename
-iprint the MIME type
-zlook inside compressed files
Security use

Extensions lie. 'photo.jpg' might really be an ELF executable or a script; file reveals it.

kali@kali: ~
kali@kali:~$ file photo.jpg report.pdf invoice.pdf.sh
photo.jpg: JPEG image data, JFIF standard 1.01
report.pdf: PDF document, version 1.7
invoice.pdf.sh: Bourne-Again shell script, ASCII text executable
kali@kali:~$ file -i /usr/bin/ls
/usr/bin/ls: application/x-pie-executable; charset=binary
kali@kali:~$
▶ Practice Rename a text file to image.png, then run file on it. What does it report?

10/50 Text Processing

grep

Searches text for lines matching a pattern or regular expression.

grep [options] pattern [file...]

-icase-insensitive
-rsearch directories recursively
-vinvert: show non-matching lines
-Eextended regex
-ccount matches
Security use

The number one log-analysis tool: find failed logins, error codes or indicators of compromise.

kali@kali: ~
kali@kali:~$ sudo grep -c 'Failed password' /var/log/auth.log
37
kali@kali:~$ sudo grep 'Failed password' /var/log/auth.log | tail -2
Oct 24 08:51:02 kali sshd[2210]: Failed password for root from 192.168.56.23 port 50412
Oct 24 08:51:05 kali sshd[2210]: Failed password for root from 192.168.56.23 port 50418
kali@kali:~$ grep -rEi 'password|secret' ~/project/config
config/app.env:DB_PASSWORD=TODO_change_me
kali@kali:~$
▶ Practice Search /var/log/auth.log for 'Accepted' to list successful logins on your machine.

awk

A pattern-scanning language for extracting and reshaping columns of text.

awk 'pattern { action }' file

-Fset the field separator
$1, $NFfirst field, last field
NRcurrent line number
Security use

Pull specific columns out of logs, e.g. the source IP of every failed login.

kali@kali: ~
kali@kali:~$ awk -F: '$7 ~ /bash|zsh/ {print $1}' /etc/passwd
root
kali
postgres
analyst
kali@kali:~$ sudo grep 'Failed password' /var/log/auth.log | awk '{print $(NF-3)}' | head -3
192.168.56.23
192.168.56.23
192.168.56.41
kali@kali:~$

15/50 Text Processing

uniq

Filters or counts adjacent duplicate lines (sort first).

uniq [options] [file]

-cprefix lines with their count
-donly show duplicated lines
-uonly show unique lines
Security use

The classic 'who is hammering my SSH?' pipeline: grep, extract, sort, uniq -c, sort -rn.

kali@kali: ~
kali@kali:~$ sudo grep 'Failed password' /var/log/auth.log \
| awk '{print $(NF-3)}' | sort | uniq -c | sort -rn
29 192.168.56.23
6 192.168.56.41
2 192.168.56.7
kali@kali:~$
▶ Practice Build the pipeline above on your own auth.log. Which source has the most failures?

uid=1001(analyst) gid=1001(analyst) groups=1001(analyst)

-llist what you are allowed to run
